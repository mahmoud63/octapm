# Installable app, offline outbox and push (OCTA-MOB-PWA-018)

A site engineer in a basement can raise punch items, observations,
photos, inspections and daily reports with no signal; everything uploads
in order when they reach the office, without duplicates. Sheets saved
for offline use open without a connection, and assignments and mentions
arrive as push notifications even when the app is closed.

## Installable app

* `frontend/vite.config.ts` runs `vite-plugin-pwa` in `injectManifest`
  mode with `src/sw.ts` as the service worker. The manifest (name,
  standalone display, dark theme, 192 / 512 / maskable icons under
  `public/icons`, generated by `frontend/scripts/make-pwa-icons.mjs`) and
  the iOS home-screen meta tags in `index.html` make the app installable
  on Android, desktop and iOS 16.4+.
* `main.tsx` registers the worker in production builds (`registerType:
  'prompt'`): a toast offers **Reload** when a new version is ready.

## Service worker (`src/sw.ts`)

| Request | Strategy | Cache |
| --- | --- | --- |
| Built assets | precached (275 entries, ~3.6 MB incl. the PDF worker) | workbox precache |
| Navigations | app shell (`/index.html`); never for `/api`, `/docs`, `/uploads` | — |
| Files: sheet revisions (`…/file`), attachment documents, photo thumbnails | cache-first, 400 entries / 30 days | `octapm-files` |
| Other `/api/v1` GETs (not auth, notifications, billing, search) | network-first, 8 s timeout, 400 entries / 1 day | `octapm-api` |
| `push` | shows the notification (title, body, tag per record) | — |
| `notificationclick` | focuses the app and opens the record's `actionUrl` | — |

Writes never pass through the worker; the outbox owns them.

## Outbox (`src/lib/offline/*`)

* **Storage**: IndexedDB `octapm-offline` with `outbox` (queued writes:
  method, URL, JSON body or multipart fields, files as Blobs,
  `clientRequestId`, optional `tempId` / `dependsOn` / `conflict`) and
  `idmap` (temporary id → server id).
* **`sendOrQueue`**: the write goes straight to the API when online; when
  the device is offline, the request fails at the network level, or the
  record it depends on is still only a temporary id, it is queued and the
  caller gets `{ queued: true, clientRequestId, tempId }` (`isQueued()`).
* **Replay** (`syncOutbox`): on start, `online`, tab focus and every
  minute. Items replay oldest first; `{{tmp:<id>}}` placeholders in the
  URL, body or form fields are swapped for the server id once the parent
  exists (a photo queued for a queued observation waits for it). A network
  failure stops the run; 408 / 429 / 5xx keep the item queued; any other
  4xx marks it **failed** with the server's message so the user can retry
  or discard it. Successful items are removed and the affected projects'
  queries refetch.
* **No duplicates**: every queued write carries a `clientRequestId`.
  Daily reports, site diaries and inspections already replay on it; this
  card adds it to punch items / observations (`PunchItem.clientRequestId`,
  unique per project; `POST /punch` and `/punch/bulk` return the original
  item(s) with `replayed`) and to attachment uploads
  (`Attachment.clientRequestId` shared by the files of one upload; a
  replay returns the attachments already created).
* **Conflict rule**: server wins on status, client wins on drafts — a
  queued update whose record changed status on the server replays without
  its `status` field (`conflict: { statusField, baseStatus }`).
* Signing out clears the outbox, the id map and both caches.

### Offline-capable writes

| Flow | What happens offline |
| --- | --- |
| Punch item / observation (single or bulk) | queued; "Saved to the outbox" |
| Inspection instance | queued |
| Attachments / photos from any evidence panel | queued with the files |
| Daily report / site diary **submit** | queued (photos follow as attachments that wait for the report); **draft** still saves locally as before |
| Capture › Photos | draft observation queued, photos queued behind it |

Pinning a photo on a sheet still needs a connection (the pin needs the
photo id); the photo itself is queued.

## Surfaces

* **Top bar**: an outbox chip shows *Offline*, *N waiting to upload* or
  *Uploading…*; its popover lists items with retry / discard and **Sync
  now**.
* **Project › Capture** (new first module, `/projects/{id}/capture`):
  big tiles for Punch item, Observation, Photos (camera-first), Inspection,
  Daily report and Drawings, an online / offline badge and the outbox.
  Visible to anyone with punch, inspection or progress access.
* **Drawings › Offline list › Save all to this device** downloads every
  file of the offline manifest into the file cache with the bearer token
  and reports how many are on the device; the viewer reads the cache when
  offline (or when the network fails), and any sheet opened online is kept
  by the worker anyway.
* **Settings › Notifications**: *Push on this device* card (enable /
  disable, send a test, list and forget devices, iOS guidance) and a
  **Push** switch per category next to In-app and Email.

## Push (backend)

* `PushSubscription` table (endpoint unique, `p256dh`, `auth`, user
  agent, platform, failure count); `NotificationPreference.pushEnabled`.
* `services/push.service.js` wraps `web-push`: `VAPID_PUBLIC_KEY`,
  `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (mailto: or https URL) configure
  it — without keys push is reported unavailable and attempts are skipped.
  Generate keys with `npx web-push generate-vapid-keys`.
* `createNotifications` adds a `push` delivery attempt for recipients who
  have a registered device and `pushEnabled` for the category, then flushes
  shortly after the transaction commits; the notification scheduler
  retries pending attempts (3 tries, backoff). 404 / 410 from the push
  service, or five failures in a row, remove the device.
* Endpoints: `GET /notifications/push/public-key`, `GET/POST/DELETE
  /notifications/push/subscriptions`, `POST /notifications/push/test`;
  `PUT /notifications/preferences` accepts `pushEnabled` (371 OpenAPI
  paths).

## Acceptance walk-through

1. Airplane mode → Capture › Punch item ×5, Observation ×2, Photos ×3
   → outbox shows 10+ items (photos wait for their observation) → signal
   back → items upload in order; repeating a sync creates no duplicates
   (`clientRequestId`).
2. Drawings › Offline list › Save all → airplane mode → open a sheet: it
   renders from the cache.
3. Settings › Notifications › Push on → Send a test → notification on
   Android / desktop and on iOS 16.4+ when installed to the Home Screen.
