# OctaPM Mobile — iPhone and iPad Verification Guide

**Audience:** the engineer who will produce the first iOS build and run the device checks.
**Status:** written on 2026-09-18 from the official Expo and Apple documentation; every version and rule below carries its source. Nothing here has been executed: this machine is Windows 11, so **IOS NATIVE LOCAL BUILD REQUIRES MACOS OR A SUPPORTED REMOTE BUILD SERVICE**. The device checks themselves are the twelve rows in the [native capability register](OCTAPM_MOBILE_NATIVE_VERIFICATION.md).

## 1. What the app is, and what that implies

Expo SDK 57 (`expo ~57.0.23`), React Native 0.86.3, React 19.2.3, expo-router. Bundle identifier `com.octapm.app`. `app.json` already declares `supportsTablet: true`, `requireFullScreen: false`, an unlocked orientation, the associated domains `applinks:app.octapm.com` and `applinks:octapm.com`, and the usage strings for camera, photo library and Face ID. Nothing in the app configuration needs changing to start.

Two capabilities this app uses fall on the paid side of Apple's line: **push notifications** and **associated domains** (universal links) both require the Apple Developer Program, which is 99 USD per membership year ([Apple: compare memberships](https://developer.apple.com/support/compare-memberships/), [enrol](https://developer.apple.com/programs/enroll/)). A free personal team gets on-device testing through Xcode with App IDs, devices and provisioning profiles that expire after seven days, and cannot exercise push or universal links at all. Expo states plainly that builds that run on an iPhone require a paid account for signing ([Expo: create a build](https://docs.expo.dev/develop/development-builds/create-a-build/)).

## 2. Three things this project needs before the first build

These are missing today and are not defects in the app; they are set-up steps.

1. **`expo-dev-client` is not a dependency.** A development build with `"developmentClient": true` needs it: `npx expo install expo-dev-client` ([Expo: set up your environment](https://docs.expo.dev/get-started/set-up-your-environment/?mode=development-build&platform=ios&device=physical)).
2. **There is no `eas.json`.** `eas build:configure` creates it ([Expo: build setup](https://docs.expo.dev/build/setup/)).
3. **`app.json` has `extra.eas` with no `projectId`.** `expo-notifications` needs it: the app calls `getExpoPushTokenAsync({ projectId })`. `eas init` or `eas build:configure` fills it in ([Expo: push notifications setup](https://docs.expo.dev/push-notifications/push-notifications-setup/)).

## 3. Route A — on a Mac

| Requirement | Version | Source |
|---|---|---|
| Xcode | 26.4 or later | [Expo SDK 57 support table](https://docs.expo.dev/versions/latest/) |
| macOS | Tahoe 26.2 or later (what Xcode 26.4 itself requires) | [Xcode 26.4 release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-26_4-release-notes) |
| iOS deployment target generated by prebuild | 16.4 | [SDK 57 bare template Podfile](https://github.com/expo/expo/blob/sdk-57/templates/expo-template-bare-minimum/ios/Podfile) |
| Minimum iOS the app supports | 16.4 | as above |
| Node | 22.13 or later | [Expo SDK 57 support table](https://docs.expo.dev/versions/latest/) |

Also install the current Xcode Command Line Tools and at least one iOS Simulator runtime ([Expo: set up your environment](https://docs.expo.dev/get-started/set-up-your-environment/?mode=development-build&platform=ios&device=physical)).

```bash
cd mobile
npm install
npx expo install expo-dev-client
npx expo prebuild --platform ios --clean
npx pod-install
npx expo run:ios                      # simulator
npx expo run:ios --device             # pick a connected iPhone or iPad
npx expo run:ios --configuration Release --device
```

`npx expo run:ios` runs `expo prebuild` itself when `ios/` is absent, and `--clean` is the safest way to regenerate ([Expo: prebuild](https://docs.expo.dev/workflow/prebuild/), [local app development](https://docs.expo.dev/guides/local-app-development/)). Whether pods are installed automatically is **not stated** in those pages, so run `npx pod-install` explicitly rather than assume.

To raise the deployment target, SDK 56 and later take `ios.deploymentTarget` in the app config as `"MAJOR.MINOR"`; the old `expo-build-properties` property is deprecated in its favour ([Expo: app config](https://docs.expo.dev/versions/latest/config/app/), [build properties](https://docs.expo.dev/versions/latest/sdk/build-properties/)).

## 4. Route B — from this Windows machine, through EAS Build

No Mac is needed: EAS builds iOS on Expo's own Mac hosts, and `eas submit` runs on Windows ([Expo: build infrastructure](https://docs.expo.dev/build-reference/infrastructure/), [submit for iOS](https://docs.expo.dev/submit/ios/)). `eas build --local` is **not supported on Windows** ([Expo: local builds](https://docs.expo.dev/build-reference/local-builds/)), so the cloud path is the one to use here.

```bash
npm install --global eas-cli
eas login
cd mobile
eas build:configure                                  # writes eas.json and the EAS projectId
eas build --platform ios --profile development       # development build for a registered device
eas build --platform ios --profile preview           # production-like, internal distribution
eas build --platform ios --profile production        # store-ready
eas build:run -p ios --latest                        # install a simulator build on a Mac
eas submit --platform ios                            # TestFlight
```

Profiles: **development** carries `expo-dev-client` and internal distribution; **preview** is production-like without dev tools; **production** is store-ready and cannot be sideloaded ([Expo: eas.json](https://docs.expo.dev/build/eas-json/)).

**Credentials.** EAS manages the distribution certificate, the provisioning profile and the APNs key for you, prompting once for an Apple Developer Program sign-in and keeping them on EAS servers; afterwards builds do not need access to the Apple team. `eas credentials` views, removes and regenerates them. One distribution certificate per account, provisioning profiles expire after twelve months, and an account may hold at most two APNs keys ([Expo: managed credentials](https://docs.expo.dev/app-signing/managed-credentials/), [app credentials](https://docs.expo.dev/app-signing/app-credentials/)).

**Getting the build onto a device.** Internal distribution is ad hoc signing with a device allowlist baked in at build time: register devices with `eas device:create`, list them with `eas device:list`, and re-sign for newly added ones with `eas build:resign`. Apple's limit is 100 iPhones per year ([Expo: internal distribution](https://docs.expo.dev/build/internal-distribution/)). Testers install from the build's URL or QR code, or over USB with Expo Orbit ([Expo: iOS development build for devices](https://docs.expo.dev/tutorial/eas/ios-development-build-for-devices/)). TestFlight goes through `eas submit` with an App Store Connect API key; a build appears there after ten to fifteen minutes of processing ([Expo: submit for iOS](https://docs.expo.dev/submit/ios/)).

**Cost.** The free plan includes fifteen iOS builds a month, one concurrency, a 45-minute timeout and a low-priority queue; paid tiers start at 19 USD a month ([Expo pricing](https://expo.dev/pricing)) — confirm before committing, since pricing changes.

## 5. Push notifications

The app registers its Expo push token on sign-in and sends it to `POST /notifications/push/subscriptions` with `provider: "expo"`; the server sends through Expo's push API. On the Apple side:

- A paid Apple Developer Program membership is required to generate the APNs key ([Expo: push notifications setup](https://docs.expo.dev/push-notifications/push-notifications-setup/)).
- `eas build` synchronises capabilities with the Apple Developer Console automatically, including Push Notifications (`aps-environment`) and Associated Domains; opt out with `EXPO_NO_CAPABILITY_SYNC=1` ([Expo: iOS capabilities](https://docs.expo.dev/build-reference/ios-capabilities/)). Beyond enrolling and signing in when prompted, no manual portal work is documented as necessary.
- Without EAS Build, run `eas credentials` and set up the push key by hand ([Expo: managed credentials](https://docs.expo.dev/app-signing/managed-credentials/)).
- The Simulator **can** receive push from Xcode 14 and later on macOS 13+ with iOS 16+, on Apple silicon or T2 hardware, against the APNs **Sandbox**, with simulator-specific tokens ([Expo](https://docs.expo.dev/push-notifications/push-notifications-setup/), [Xcode 14 release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-14-release-notes)). A real device is still the honest check for delivery from the OctaPM server.

## 6. Universal links

The app declares `applinks:app.octapm.com` and `applinks:octapm.com` without a protocol, which is correct; including `https://` is the usual cause of universal links not working ([Expo: iOS universal links](https://docs.expo.dev/linking/ios-universal-links/)).

- Host the association file at `https://<domain>/.well-known/apple-app-site-association` — no file extension, valid HTTPS certificate, **no redirects** ([Apple: supporting associated domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains)).
- **Two files are needed here.** A file on `octapm.com` serves `applinks:octapm.com` and wildcard subdomains, but **not** the explicitly declared `app.octapm.com`; that subdomain needs its own file ([Apple TN3155](https://developer.apple.com/documentation/technotes/tn3155-debugging-universal-links)).
- Use Apple's current format — an `appIDs` array with a `components` array — not the legacy `appID`/`paths` pair, and never mix the two. The identifier is `<Team ID>.com.octapm.app` ([Apple: supporting associated domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains), [TN3155](https://developer.apple.com/documentation/technotes/tn3155-debugging-universal-links)). Expo's page still shows the legacy shape.
- A required `Content-Type` is **not documented** by Apple; `application/json` is conventional. The uncompressed file must stay under 128 KB ([Expo](https://docs.expo.dev/linking/ios-universal-links/)).
- Devices fetch the file from Apple's CDN, which refreshes within 24 hours and re-checks about weekly; there is no CDN invalidation, so reinstall the app to pick up a new file, or append `?mode=developer` to the associated domain during development ([Apple: supporting associated domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains), [TN3155](https://developer.apple.com/documentation/technotes/tn3155-debugging-universal-links)).

Verify, in Apple's own steps ([TN3155](https://developer.apple.com/documentation/technotes/tn3155-debugging-universal-links)):

```bash
curl -v https://app.octapm.com/.well-known/apple-app-site-association      # 301/302 = redirect, unsupported; 403/404 = blocked
curl -A "MyAgent-Bot/*" https://app.octapm.com/.well-known/apple-app-site-association
sudo swcutil dl -d app.octapm.com
sudo swcutil verify -d app.octapm.com -j ./apple-app-site-association -u "https://app.octapm.com/projects/<id>/rfi?recordId=<id>&source=rfi"
```

On the device, paste the link into Notes and long-press it; typing a universal link into Safari's address bar **never** opens the app. Settings → Developer → Associated Domains Development → Diagnostics checks a full URL.

## 7. iPad

`supportsTablet: true`, `requireFullScreen: false` and an unlocked orientation are already set, which is the configuration Apple is moving everyone toward: `UIRequiresFullScreen` is deprecated from iPadOS 26 and ignored from iOS/iPadOS 27, and a resizable app must provide a launch screen and support all orientations ([Apple: UIRequiresFullScreen](https://developer.apple.com/documentation/BundleResources/Information-Property-List/UIRequiresFullScreen), [TN3192](https://developer.apple.com/documentation/technotes/tn3192-migrating-your-app-from-the-deprecated-uirequiresfullscreen-key)). Nothing to change; the app must simply survive arbitrary window sizes.

It is built to: every layout decision comes from `useWindowDimensions` through the width classes in `src/hooks/useLayout.ts`, which React Native updates on every size change, and the master–detail split is driven by that width rather than by a device check ([React Native: useWindowDimensions](https://reactnative.dev/docs/usewindowdimensions), [Dimensions](https://reactnative.dev/docs/dimensions)). The device check is to confirm it in Slide Over, in Split View and across a rotation with a record open.

## 8. What the Simulator cannot certify

| Capability | Simulator | Source |
|---|---|---|
| Camera and microphone | Not available | [Apple Simulator guide](https://developer.apple.com/library/archive/documentation/IDEs/Conceptual/iOS_Simulator_Guide/TestingontheiOSSimulator/TestingontheiOSSimulator.html) (archived; use for hardware only), [expo-camera: device only](https://docs.expo.dev/versions/latest/sdk/camera/) |
| Keychain / SecureStore under biometrics | Behaves differently: a simulator does not demand biometric authentication when reading a protected secret, a real device does | [expo-secure-store](https://docs.expo.dev/versions/latest/sdk/securestore/) |
| Face ID | Simulated enrolment and match exist in the Simulator's Features menu, but Face ID needs a development build in any case | [expo-local-authentication](https://docs.expo.dev/versions/latest/sdk/local-authentication/) |
| Push delivery | Possible on Xcode 14+/macOS 13+/iOS 16+, Apple silicon or T2, Sandbox only | §5 above |
| Barcode scanning | Follows the camera | as camera |

Two `expo-secure-store` facts worth carrying into the pilot brief: stored secrets survive an app uninstall when the app is reinstalled with the same bundle identifier, and an entry written with `requireAuthentication: true` becomes unreadable if the person's biometric enrolment changes ([expo-secure-store](https://docs.expo.dev/versions/latest/sdk/securestore/)).

## 9. Recording the result

Run the twelve device checks in the [native capability register](OCTAPM_MOBILE_NATIVE_VERIFICATION.md) on at least one iPhone and one iPad. For each row record the build id, the device model, the iOS version, the date, the tester and the outcome, and move the row to NATIVE-VERIFIED only with that evidence. Until then the app's verdict stays as the [certification report](OCTAPM_MOBILE_CERTIFICATION_REPORT.md) has it.
