# OctaPM on AWS — staging

The ECS-based staging stack (owner decisions 2026-10-11). It replaces nothing:
the old single-EC2 stack in `infrastructure/terraform` is left as it is and is
not used.

```
infrastructure/aws/
├── bootstrap/   remote-state bucket (S3, encrypted, versioned, TLS-only; S3 native lock file)
└── staging/     the staging application stack (state in that bucket)
```

Account `977476317319` (OctaPM Staging), region **us-east-1**, profile
`octapm-staging` (IAM Identity Center). Both stacks set
`allowed_account_ids`, so they refuse any other account. Budgets are managed
from the organisation's management account, not here.

## Order of operations

```powershell
$env:AWS_PROFILE = 'octapm-staging'      # aws sso login --profile octapm-staging first
cd infrastructure/aws/bootstrap
terraform init; terraform apply           # once: the state bucket
cd ../staging
Remove-Item backend_override.tf           # only present if a pre-bootstrap plan was made
terraform init                            # now on the S3 backend
terraform plan -out staging.tfplan; terraform apply staging.tfplan
```

A plan made before the bucket exists uses a gitignored `backend_override.tf`
(`backend "local"`); delete it before the real `init`.

## What the stack creates

- **Network:** a dedicated VPC `10.40.0.0/16` in two AZs. Public subnets hold the ALB and the Fargate tasks; private database subnets hold RDS and have no internet route. There is no NAT gateway; the tasks use public IPs for outbound calls. An S3 gateway endpoint is included.
- **Security groups:** CloudFront (origin-facing prefix list) → ALB :80 → API :5000 → RDS :5432. The worker accepts no inbound traffic. RDS is never reachable from `0.0.0.0/0`.
- **RDS:** PostgreSQL 16 on `db.t4g.micro`, 20 GB gp3, encrypted, single-AZ, not public. Backups are kept 7 days, deletion protection is on, and a final snapshot is taken on deletion. The CA is `rds-ca-rsa2048-g1`.
- **ECS Fargate:** one cluster with two services.
  - `api`: 0.5 vCPU / 1 GB, behind the ALB, rolling deploys with circuit-breaker rollback.
  - `worker`: 0.25 vCPU / 0.5 GB, `node src/worker.js`.
  - Both run 1 task when `services_enabled = true`. They stay at 0 until the first image exists.
- **ECR:** `octapm-staging-backend`, with immutable tags, scan on push, and a lifecycle policy (untagged images deleted after 7 days; the newest 15 kept).
- **S3:** a web build bucket (read by CloudFront only) and a private uploads bucket.
  - The uploads bucket is versioned, encrypted, blocks all public access and accepts TLS only.
  - Its CORS allows the three staging origins only.
- **CloudFront:** three distributions (`app`, `portal`, `admin`) on `*.cloudfront.net`.
  - The default behaviour serves the S3 web build.
  - `/api/*` and `/socket.io/*` go to the ALB uncached, with the origin secret header.
  - Every page carries noindex and security headers.
- **Secrets Manager:**
  - `octapm/staging/generated`, generated by Terraform: `DATABASE_URL`, the JWT, MFA and integration keys, and the CloudFront secret.
  - `octapm/staging/manual`, a container only. The owner stores its JSON value (keys: the `manual_secret_keys` output); Terraform never writes, replaces or re-labels a version of it.
- **CloudTrail:** management events only, all regions, log-file validation on, stored in its own bucket for 365 days.
- **CloudWatch:** `/octapm/staging/api` and `/octapm/staging/worker` log groups (14 days), plus 10 alarms on an SNS topic.
- **SES:** a configuration set. The sender identity is created only when `email_from_address` is set. The account is in the sandbox.

## Deploy-phase notes (not done by this stack)

- Build the backend image with `--build-arg RDS_CA_CN="Amazon RDS us-east-1 Root CA RSA2048 G1"`. The Dockerfile's default is us-east-2, and Prisma would refuse this instance. Also set `--build-arg RELEASE_GIT_SHA=<commit>`. Push the image to ECR tagged with that commit, then set `image_tag` and `services_enabled = true`.
- Run migrations with `npx prisma migrate deploy` as a one-off task (worker task definition with a command override; see the `migration_task` output). Never run `migrate reset`.
- Build the web app with `VITE_API_URL=/api/v1` and `VITE_APP_URL`, `VITE_PORTAL_URL`, `VITE_ADMIN_URL` set to the three `staging_urls`. Sync it to the web bucket and invalidate the three distributions.
- Store the value of `octapm/staging/manual` in the console ("Retrieve secret value" → "Set secret value", key/value pairs), one JSON object with every key of the `manual_secret_keys` output:
  - the Anthropic key;
  - Stripe **test-mode** values. `sk_test_` is allowed only because `APP_ENV=staging`. The four price ids, the rotation date and the ticket must be non-placeholder values; CI-style dummy values work while billing is not being tested.
- SES sandbox: verify the sender address and every recipient mailbox used for testing.
